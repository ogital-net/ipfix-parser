# CLAUDE.md — `ipfix-parser`

Guidance for AI coding agents (and humans) working in this repository.

## Project

- **Name:** `ipfix-parser`
- **Purpose:** A high-performance, zero-copy, sans-io decoder for IPFIX
  (RFC 7011) messages in Rust.
- **Status:** Pre-alpha. Public API is unstable and may change without notice.
- **License:** BSD-2-Clause.
- **Edition / MSRV:** Rust 2021, `rust-version = "1.80"`. MSRV may rise if
  there is a concrete justification; bumps are a deliberate, documented change.

## Objectives

- **RFC 7011 compliant decoder** for IPFIX messages, including templates,
  options templates, variable-length information elements, and
  enterprise-specific IEs.
- **Zero-copy:** parsed views borrow from the caller's `&[u8]`. No per-record
  heap allocation on the decode hot path.
- **Sans-io:** pure decoding. No sockets, files, async runtimes, or transport
  state. Callers feed bytes; the parser yields views.
- **Pull / iterator API:** `Message → Sets → Records → Fields`, lazy and
  resumable. The caller drives iteration.
- **Externalized template state:** templates are kept by the caller behind a
  `TemplateStore` trait. The library does not own session/observation-domain
  state.
- **Robust against malformed input:** no panics, no UB, no unbounded work on
  adversarial bytes. Validated by fuzzing.
- **Predictable performance:** aspirational target of multi-Mpps single-core
  throughput on representative traces. All performance claims are backed by
  criterion benchmarks checked into the repo.

## Non-goals

- NetFlow v5, NetFlow v9, sFlow, or other flow-export formats.
- Encoding / serialization of IPFIX messages (decoder only).
- Network, file, or async I/O. **Tokio is the expected consumer environment**,
  but the crate itself does **not** depend on tokio or any I/O runtime.
- SCTP, TLS, DTLS, or any transport-session handling.
- Stateful flow aggregation, deduplication, enrichment, or analytics.
- pcapng parsing inside the library. pcapng is a **test-fixture format only**
  and is handled by a dev-dependency (`pcap-parser`) inside `tests/` and
  `examples/`.

## Architecture (planned module layout)

```
src/
  lib.rs        crate root; re-exports; top-level docs
  error.rs      `Error` enum, `Result` alias; small, non-allocating
  header.rs     IPFIX message header (version, length, export time, seq, ODID)
  set.rs        Set header + iterator over sets within a message
  template.rs   Template & options-template record parsing; TemplateId, field spec
  store.rs      `TemplateStore` trait + bounded LRU multi-session impl (feature-gated)
  record.rs     Data record iteration driven by a resolved template
  field.rs      `FieldValue` zero-copy view; variable-length & enterprise IEs
  ie/           IANA IE registry generated by build.rs + typed accessors
  util.rs       endian / decoding helpers (`#[inline]` free functions)

build.rs        codegen for the IANA IE registry from the IANA CSV
benches/        criterion benches over byte fixtures
fuzz/           cargo-fuzz targets for header / set / record / field decoders
tests/          integration tests (tokio-based harnesses)
tests/fixtures/ real-world `.pcapng` captures checked into the repo
examples/       end-to-end usage on the tokio ecosystem (e.g. UDP receiver)
```

When the public API surface changes in a way that affects this layout, update
this section in the same change.

## Coding conventions

- **Edition / MSRV:** Rust 2021, MSRV 1.80. Pinned in `Cargo.toml`
  (`rust-version = "1.80"`).
- **Unsafe code:** permitted, but **benchmark-justified**. Default posture is
  safe-first; do not reach for `unsafe` speculatively. Any `unsafe` addition
  requires, in the same change:
  1. A criterion bench demonstrating a meaningful win over the safe
     implementation.
  2. The safe implementation kept in-tree as the fallback / reference path.
  3. A `// SAFETY:` comment on every `unsafe` block explaining the invariants.
  4. A fuzz target exercising the unsafe path.
  5. `#![deny(unsafe_op_in_unsafe_fn)]` at the crate root so each operation is
     explicit.
- **Errors:** a small, typed `Error` enum with `Debug` derived and `Display`
  written by hand. **No** `anyhow` or `thiserror` in the public API surface.
  No `panic!`, `unwrap`, or `expect` outside tests.
- **Allocations:** no allocations on the decode hot path. Anything that needs
  to allocate (owned/builder types, default `TemplateStore` impl) lives behind
  an opt-in feature flag.
- **Lints:** `#![warn(missing_docs, clippy::pedantic, clippy::nursery)]` at
  crate root, with explicit `#[allow(...)]` where justified.
- **API stability:** public types are `#[non_exhaustive]` until 1.0.
- **Endianness:** explicit `u16::from_be_bytes`, `u32::from_be_bytes`, etc.
  No `byteorder` dependency.
- **Bounds checks:** never index untrusted offsets with `[]`. Use
  `slice::get`, `split_at_checked`, `chunks_exact`, etc., that return
  `Option`.
- **Dependencies:** zero runtime dependencies on the critical path. New
  dependencies — even dev-dependencies — require explicit approval.

## Performance rules

- **Zero-copy first.** Parsers return views (`&'a [u8]` or typed wrappers
  borrowing `'a`). Owned conversions are opt-in.
- **Lazy iterators.** `#[inline]` on small accessors. Avoid intermediate
  `Vec`s on the hot path.
- **SIMD only behind `cfg` gates** with a scalar fallback. SIMD lands only
  with a criterion bench showing a meaningful win.
- **Bench-driven.** Every performance claim is backed by a criterion bench
  checked into `benches/`. If a change is "for performance," there must be a
  before/after number from `cargo bench`.

## Testing & commands

```sh
cargo test                                  # unit + integration
cargo test --all-features                   # feature matrix
cargo bench                                 # criterion benches
cargo +nightly fuzz run <target>            # fuzz targets
cargo clippy --all-targets -- -D warnings   # lint gate
cargo fmt --all -- --check                  # format gate
cargo doc --no-deps                         # build docs
```

Integration tests and examples may use tokio (as a `dev-dependency` only).
Real-world `.pcapng` captures live under `tests/fixtures/` and are read via
`pcap-parser` (also a dev-dependency).

## Agent workflow rules

- Prefer editing existing files over creating new ones.
- No new dependencies (runtime **or** dev) without explicit approval.
- Any `unsafe` addition requires, in the same change: a criterion bench
  showing the win, a `// SAFETY:` comment, and a fuzz target covering the
  path.
- Public API changes require updating the **Architecture** section above in
  the same change.
- Run `cargo test`, `cargo clippy --all-targets -- -D warnings`, and
  `cargo fmt --all -- --check` before declaring a task done.
- Implement what is specified. Do not add features, helpers, abstractions,
  or "improvements" speculatively. Document hooks for future work in
  comments rather than building them.
